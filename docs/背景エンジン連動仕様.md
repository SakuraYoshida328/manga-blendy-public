# Manga Blendy 背景エンジン連動仕様 v1

追加日：2026-10-12。根拠：ユーザーの連動・主役指定・配布に関する指示。

この文書をManga Blendy側の連動ルールの正本とする。特定の漫画制作アプリに依存せず、他のアプリも同じ受け渡し仕様を利用できる構成にする。**本書は追加要件であり、3モードのUI・描画制御・外部接続が実装済みであることは意味しない。**

## 1. 起動と担当範囲

- ネーム・絵コンテ工程からManga Blendyを呼び出さない。その工程でBlenderや背景生成用AIを起動しない。
- 本番作画で、背景が必要と判断したコマだけ明示的に呼び出す。全ページ・全コマの自動生成や先読み生成を既定にしない。
- Manga Blendyは必要時だけ働く背景生成エンジン。待機時はBlender・生成ワーカーを常駐させず、処理完了・キャンセル・失敗後に所有するプロセスを終了する。
- 保存済みPNGを再利用できる場合は生成を省く。資料の目次・設定・既存PNGの読み取りで生成処理を開始しない。
- ネーム、人物作画、吹き出し、文字、ページ組版は呼び出し元が担当する。Manga Blendyは場所の設定・状態・カメラと、主役指定に合う背景を担当する。
- 設定資料集の整備・構造検証は独立した資料作業として扱い、本番作画のコマ出力とジョブを分ける。これをネーム・絵コンテから背景生成を呼ぶ抜け道にしない。

優先順位は **軽さ → 必要時のみ呼び出す運用 → 背景の一貫性 → 主役に応じた線幅・情報量 → 漫画としての読みやすさ**。軽量化のために固定構造を改変することは認めない。

## 2. コマごとの主役指定

| 表示名 | 共通識別子 | 背景の主線 | 背景の情報量 | 基本用途 |
| --- | --- | --- | --- | --- |
| 人物主役モード | `character` | 人物外周線より細い | 低。主役・動作に必要な構造を残し、細部を抑える | 会話、感情、動作重視 |
| バランスモード | `balanced` | 人物と背景が読める中間設定 | 中。位置関係と人物の見やすさを両立 | 空間と人物の関係を見せるコマ |
| 背景主役モード | `background` | 人物外周線と同等まで許容 | 高。構造とその場所らしい特徴を多めに保持 | 場面開始、場面転換、空間全体の提示 |

コマ出力時に3モードを選べるUIをManga Blendy本体に用意し、外部アプリからも共通識別子で指定可能にする。基本値は人物主役。目的が明示されている場合は表の用途に従って選ぶ。動作重視でも足の接地・距離・技の成立に必要な床や構造は残す。

「背景が必要か」「主役モード」「カメラ距離」は別の設定。人物主役でも必要な背景を出せる。背景省略コマに主役モードが記録されていても、それだけを理由に生成しない。背景比率の参考値は全体・シーンの目安であり、ページ単位の生成ノルマにしない。

## 3. 線幅・情報量・トーン

### 線幅

人物の外周線の代表線幅を、最終画像上のピクセル幅 `W` として受け取る。同じ最終寸法で比較し、背景の作業画像を縮小する場合は換算する。人物の線幅が渡されない場合は作品の線幅設定・画質参照から決め、その根拠が推定なら出力記録に残す。人物の線幅を勝手に変更して条件を満たしてはいけない。

初期調整案は、背景主線を人物主役 `0.6W`、バランス `0.8W`、背景主役 `1.0W` とする。比率は実装の初期値であってユーザー指定の確定値ではない。最終サイズの見え方で調整し、人物主役では必ず `背景主線 < W` を守る。細くするために線をぼかしたり、低解像度にしたりしない。線幅だけでなく、重なり・黒・トーンによって人物が埋もれないことを確認する。

### 情報量

低・中・高の描画プリセットを同じ3D・詳細参照に適用する。画面で不要な細い窓枠、机脚の補助線、金具、装飾、掲示物の細部、小物の細部から調整する。

- 正本の窓・戸の数、開口形状、位置、寸法、家具の整列、前後・左右、遮蔽、物体IDは変更しない。
- 窓の細分割を省く場合も、採用した二段構造など識別に必要な特徴を保つ。省略を別の窓構造として見せない。
- 机脚は余分な線を減らしても、支持部や接地が分かる表現を残す。宙に浮く家具や別形の家具にしない。
- 物語上重要な小物・掲示物は、位置や存在を勝手に消さない。内容の省略が物語を変える場合は保護する。
- 絵から省く細部も正本と詳細参照には残す。描画上の省略は、SceneStateの不在・移動・収納とは区別する。
- 人物が重なる領域の線を抑える機能は、将来渡される人物領域を利用する場合だけ適用する。領域がない段階で推測して背景を欠損させない。

トーンもモードに合わせて抑制・保持する。人物主役は薄く少なく、バランスは中間、背景主役は形・奥行きが伝わる範囲で増やす。背景主役でも画面全体を濃くすることを目的にせず、作品の白黒品質を優先する。

## 4. 他のアプリとの共通受け渡し

最初は **JSONの出力要求 → Manga Blendyの単発ジョブ → PNGと結果JSON** でよい。手動の受け渡しから始め、同じ形式を将来のCLI・ローカルAPI・アプリ別アダプターで利用する。特定の制作アプリ用プラグインや常駐サーバーをMVPの必須依存にしない。

以下は新設する要求形式の例。現在のAPIにそのまま送れる形式ではない。

```json
{
  "contract": "manga-blendy.background-request",
  "schema_version": 1,
  "request_id": "request_001",
  "context": {
    "stage": "production_drawing",
    "document_id": "episode_01",
    "page_id": "page_006",
    "panel_id": "panel_03"
  },
  "scene": {
    "project_id": "classroom_project",
    "revision_id": "adopted_revision",
    "state_id": "classroom_state_001"
  },
  "camera": {
    "camera_id": "rear"
  },
  "render": {
    "focus_mode": "character",
    "character_outline_px": 3.0,
    "output_size_px": [1200, 800],
    "passes": ["composite"]
  }
}
```

| 入力 | 扱い |
| --- | --- |
| `contract` / `schema_version` | 新しい連動要求の名前と版。正本SceneRevisionの版とは別 |
| `request_id` | 呼び出しと結果を対応させる。再送時の重複生成を防ぐ |
| `context.stage` | 背景生成は `production_drawing` のみ。ネーム・絵コンテ・不明な工程は生成前に拒否 |
| 文書・ページ・コマID | 呼び出し元の識別子。ページ・コマを持たないアプリはそのIDを省略し、文書IDで追跡する |
| `scene` | 採用するプロジェクト・改訂・状態を明示。黙って最新へ差し替えない |
| `camera` | 既存カメラID、または既存CameraPresetと同形式のコマ用カメラ指定のいずれか。指定漏れを勝手な視点で補わない |
| `focus_mode` | 3モードのいずれか。UIは初期値を表示するが、外部要求では明示必須 |
| `character_outline_px` | 最終画像上の人物外周線幅。省略時の参照と実際の採用幅は結果に記録 |
| `output_size_px` | 最終背景PNGの幅・高さ。固定のプレビュー寸法を本番寸法とみなさない |
| `passes` | MVPは `composite` のみ。未対応の分離出力を要求された場合は未対応と返す |

結果JSONには契約名・版・request_id、成功／失敗／キャンセル、採用したrevision_id・state_id、カメラ、主役モード、実際の線幅・情報量・トーン設定、入力ハッシュ、PNGの相対パス・寸法・ハッシュ、推定・省略内容、エラーを記録する。ジョブが実際に生成したファイルだけを成果物として返す。

受け渡しパッケージ内の成果物パスは相対パスにし、配布先のドライブ名やユーザー名を固定しない。保存先ルートはManga Blendyで指定・許可した場所とし、外部アプリが任意パスや実行コマンドを指定する方式にしない。通信・ファイル読込・認証の責務はアダプターへ分離し、レンダラーへ他アプリ固有の名前やSDKを持ち込まない。

MVPの他アプリ対応は共通パッケージの受け渡しを指す。任意の外部アプリへ自動で配置できることや、PSD・CSPへの直接操作が完了していることは意味しない。

## 5. 軽い実行とキャッシュ

1. 必要なコマか、工程・要求の版・採用改訂・状態・カメラ・モードが有効かを確認する。要求の確認でAIを呼ばない。
2. 正本・状態・外観参照・カメラ・主役モード・採用線幅・情報量・トーン・最終寸法・レンダラー版を含む入力ハッシュを計算する。
3. 一致する保存済みPNGと結果の整合性を確認できれば再利用し、Blenderを起動しない。別モードや別寸法のPNGを同一結果として使わない。
4. 未生成の場合のみ、既存の単一ワーカーで要求したカメラ1枚を生成する。本番のコマ1枚のために常に4方向や3モード全部を生成しない。
5. 結果を保存・検証して返し、所有するワーカーとBlenderを終了する。自動再起動・無限再試行・未完了ジョブの無断再開をしない。

資料集の初回4方向検証は別のジョブとして維持できる。本番作画の1コマ出力へ、資料集作成・AI再解析・4方向検証を毎回連結しない。

既存設定からの背景レンダリングにAI再解析は不要。AIが必要な資料解析では、このプロジェクトはChatGPT Plusの利用枠だけを使い、APIキー、別課金、クレジットへの自動切替を使わない。枠切れならAI処理を停止する。認証情報を他アプリとの要求・結果JSONやログに含めない。

## 6. 拡張と既存実装への追加順

MVPは線とトーンを含む最終白黒PNG1枚。将来は `main_lines`（主線）、`auxiliary_lines`（補助線）、`decoration_lines`（装飾線）、`tones`（トーン）を任意の出力として追加できるようにする。分離画像は同じカメラ・最終寸法・座標・余白を使う。今は分離画像を毎回生成しない。

教室・道場・個人の部屋など、登録済みの場所に同じ主役モードを適用する。場所ごとに別の連動方式を作らない。未作成の場所を利用可能と表示しない。

現状の `SceneRevision`・`SceneState`・参照辞書を正本として保持し、コマ用の出力要求を別データにする。主役モードを正本へ混ぜたり、固定3Dをモードごとに複製したりしない。旧資料と既存の4方向検証は継続して読み込めるようにする。

実装順は次の最小構成とする。

1. **要求型と検証**：共通出力要求・結果型、工程ゲート、3モード、カメラ1枚、相対パスとキャッシュ条件を追加する。既存の正本JSONへ直接フィールドを足して壊さない。
2. **単発の描画**：`jobs.py` と `blender_adapter.py` に本番1枚の出力経路を追加する。既存の資料検証4枚経路とは区別する。既存の型・出力検証は4カメラを要求するため、その条件を全体で撤廃せず、ジョブの目的に応じて適用する。
3. **3モード**：Blenderワーカーで線幅、描画する線の種類、トーンを要求に従って選択する。構造や物語状態を変更しない。本体UIにもモード選択と最終サイズ確認を追加する。
4. **共通受け渡し**：JSON要求の取込とPNG・結果JSONの書出しを追加する。アプリ名に依存しないパッケージから始め、必要になったアプリだけアダプターを作る。
5. **受入れ確認**：同じ場所・状態・カメラの3モードを比較し、構造一致と人物の見やすさを別々に検証する。待機時のBlender不在、1要求1カメラ、キャッシュ利用、終了・キャンセル、工程拒否も確認する。

現在は既存の資料集・状態・Blender4視点出力があり、教室実験には漫画調の線・トーン付き試作がある。2026-10-12に本体の3モード制御、独立した線幅と詳細設定、1視点要求、工程ゲート、保存3Dを使う既存MCP出力、キャッシュを追加した。/background-contract を共通契約とする。外部アプリ固有の接続、配布用認証、線とトーンの分離は未実装。素材分類と制限は 素材分類と漫画仕上げ.md を参照。

## 7. 配布に含めるもの

アプリ本体、利用手順、この仕様、実装した時点の契約スキーマ・個人データを含まないサンプルを配布対象にする。特定アプリの導入、ユーザーの漫画原稿、教室実験データ、認証情報、絶対パス、実行ログは必須配布物にしない。

他アプリ側には共通要求の作成と結果PNGの配置だけを求める。機能が不足する場合は未対応を明示し、Manga Blendyの正本・状態管理・描画の責務を呼び出し元へ散らさない。

# 素材分類と漫画仕上げ

配置と物語上の状態は従来のCategory・management_role・SceneStateで保持する。描画処理は別のMaterialClassで選択する。

| 素材分類 | 担当 | 処理 |
|---|---|---|
| building | 建物 | 固定形状、開口部、主要線 |
| standard_furniture | 通常家具 | 配置、輪郭、材質参照 |
| fabric_furniture | 布家具 | 接触・遮蔽を保つ滑らかな形状、布参照、弱い輪郭 |
| standard_prop | 通常小物 | 状態を継承、必要時に追加 |
| fabric_prop | 布小物 | 布の表面処理、必要時の追加候補 |

SceneRevision版3にはmaterial_classとcomponents、任意のsaved_geometryを追加した。版1・2は従来のJSONを読み込め、表示時に元ファイルを移行しない。新規解析と明示した改訂で分類を追加する。自動分類は暫定推定。すべての椅子を布張りにしない。部品は物体ID＋component_idで識別し、参照IDはその物体の辞書だけを指す。ベッドは枠と布、植物は鉢と葉を同じ物体の部品として管理する。

本は軽さを優先し、棚・台と段ごとのdetail_groupsで仮冊数、参照、所属IDを保存する。配置が同じ支持物に結び付いた通常の本が3冊以上なら、新規計画でグループを作り、細密形状を要求しない。個々のIDや参照を消さず、冊数の根拠は推定のままとする。重要な本はグループ化しない。グループ内の本を物語上重要と指定すると、新しい改訂でグループから外し、詳細3Dの再準備後に個別状態を変更できる。背景のまとまりのまま1冊だけ勝手に移動・消失させない。

準備済みシーンでは複数の本の管理IDを参照付き軽量メッシュにまとめ、背表紙の表面参照を使える。外形の最小限の奥行きは、別角度で遮蔽が成立するために保持する。原画像の本のタイトルや総冊数を推定で確定しない。一般のテンプレート経路は簡単なproxy形状を使用する。任意の本棚で同品質の表面画像を自動作成する機能は未実装。

## 布の役割分担

Blenderで輪郭、厚み、主要なしわ、たるみ、接触と遮蔽を管理する。平滑化した面と連続法線を使い、低ポリゴンの面の陰影を完成表現にしない。参照画像の確認済みの表面から花柄のインクや編み目を抽出し、物体のUVへ適用する。元画像全体や家具を含む切り出しを背景として貼らない。表面画像は.blend内にパックし、物体・部品・参照IDと由来を記録する。

布の自然なしわの配置まで自動で正確に復元する汎用機能は未実装。本体は準備済み3Dの表面処理と撮影を再利用できる。一般テンプレートにも部品素材、面の平滑化と布用の面取りを適用するが、新規の任意の部屋にも同品質が自動で出るとは保証しない。

v3では任意の二段階仕上げを追加した。3DのPNGを構造基準、元画像を画風参照として分け、利用枠内の外部編集環境で作ったPNGを候補として取り込む。基準画像は保持し、簡易輪郭検査と利用者の構造・外観確認で採否を決める。本体からの自動画像生成、深度・物体/部品マスクによる完全な輪郭固定は未実装。輪郭・配置・窓・戸・接触線を自由に変更させない。[現在の実装と制限](AI-capabilities.md)を参照。透過小物の登録と配置、服の再追加は現状未対応。

## 1視点出力の実装

`POST /api/projects/{project_id}/states/{state_id}/render-image`

```json
{
  "stage": "production_drawing",
  "camera_id": "01_window",
  "render": {
    "focus_mode": "character",
    "character_outline_px": 1.5,
    "detail_level": "high",
    "resolution": [1448, 1086]
  }
}
```

工程はproduction_drawingかreference_validation。ネーム・絵コンテは拒否する。既存の画面セッションのトークンが必要で、未知のカメラ、任意Pythonコード、外部パスは受け付けない。

人物主役の主線は基準人物線の0.6倍、バランスは0.8倍、背景主役は1.0倍。布線は主線の0.65倍、細部線は0.42倍。detail_levelは主役モードと独立し、未指定時だけモードに連動する。画像表面の詳細・トーンの強さも調整する。弱めるのは描画強度で、家具や窓枠・物体の存在を消さない。線・トーンのレイヤー分離出力は未実装。

saved_geometryはプロジェクト内の相対.blendパスとSHA256。準備済み3Dがない資料は、漫画出力時にエラーにする。従来の簡易模型へ自動で切り替えない。形状・配置の改訂で保存3Dの登録は無効にし、準備し直す。候補を採用する際は保存3Dを改訂ディレクトリへコピーし、ZIPにも含める。

既存MCPアドオンのローカルコマンド接続を利用する。新規インストール、MCP不要化、自動セットアップは今回行わない。アプリの閲覧・キャッシュ利用でBlenderを起動しない。未生成の出力時は既存MCP接続が必要。所有していないBlenderを勝手に終了しない。停止要求は現在の1枚を完了してシーンを復元する方式で、レンダリング途中の即時中断は行わない。

キャッシュには正本・状態・カメラ・素材3Dのハッシュ・レンダラー・モード・線幅・詳細・解像度・サンプル数を含める。PNGのハッシュも検査する。1要求はPNG1枚と結果JSON。元のBlenderシーンは一時的に読み込んだシーンの撮影後に復元し、所有した一時データだけを除去する。

AI呼出しはこの出力経路に含まれない。APIキー・追加課金への切替はない。他アプリからの接続はこのJSON契約と結果PNG/JSONを基準にできるが、外部アプリ固有の接続部や配布用認証は未実装。

## 外観と構造の受入れ

構造は物体ID、状態、世界座標、窓の分割、保存3Dハッシュと再オープンで検査する。外観は元画像・旧出力・改善出力を並べ、布の面、柔らかさ、柄の尺度、木目、線の強弱を別に目視確認する。構造の検査が通っても外観の完成とはしない。見えない入口側や寸法は推定のまま保持する。

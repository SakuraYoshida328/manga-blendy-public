# 複雑な部屋の整理と画像連動

追加日：2026-10-12。複雑な部屋を扱うための本体のデータと処理方針。現在の監査結果は implementation-audit.md を参照。

## 実装した流れ

1. Codex/ChatGPTで元画像を解析し、建物・固定家具・自由小物・準固定装飾を分類する。
2. 元画像と解析JSONをアプリへ取り込む。元ファイルのSHA256を照合し、別画像の解析結果を受け付けない。
3. 建物・家具・物語上重要なもの・重要度未確認のものを保護する。観葉植物の鉢、カーペットは固定家具として扱う。
4. 運用予算を超える自由小物を、詳細な形状から輪郭用の形状へ段階的に軽量化する。ID、寸法、配置、向き、存在、状態、画像参照は削除しない。予算を増やした場合は、保持したテンプレートから詳細形状へ戻せる。
5. 物体IDに対応する詳細画像を保存する。表面部分として確認された画像は、指定した部品・面へ適用する。模様・素材感は画像の色、微細な毛並み・凹凸は画像によるバンプで表現する。
6. 同じ状態の4方向を確認し、Blenderファイルを再読込して物体ID・参照IDを検証する。画像は `.blend` 内にも保存する。

建物・家具の形・位置・特徴の再現を優先する。表面画像はその立体構造に従う。建物・家具を削ったり、小物を勝手に移動したりして予算に収めない。

## 管理予算の意味

初期値は、通常の自由小物を詳細な3Dで扱う上限12個、形状の相対的な予算50,000単位。重要物や部品固有の画像が必要な物は保護する。値は最初の設定画面から変更できる。

これは**AIの管理能力を実測した値ではなく、暫定の運用予算**。実際の部屋の画像・多角度・再利用時の安定性を確認して調整する。最小形状まで整理しても保護要素が予算を超える場合は、原本・参照・設定を保存し、3Dの完成扱いにはしない。

正本の画像は保管する。形状の内部簡素化と、別のマスター画像を作ることは区別する。今回、画像生成AIによる整理済みマスター画像の自動作成は追加していない。

## 詳細画像の目印

`object_id → reference_id → crop_asset_id → 部品・面・用途` を対応関係として保存する。参照画像には元画像のハッシュ、切り出し範囲、見えている面、適用する状態バリエーションも残す。

同じ物体の位置・向きが変わっても、対応する画像は物体の面に追従する。単なる会話履歴に記憶させる方式ではない。

表面の用途は次の2つ。

| 用途 | 担当 | 例 |
| --- | --- | --- |
| `color` | 模様・濃淡・素材の見た目 | カーペット柄、布、表面の模様 |
| `bump` | 微細な凹凸の見た目 | 毛並み、繊維、細かな表面の粒子 |

形状参照の切り出しを、そのままテクスチャにはしない。人物・他の物体・輪郭・未補正の遠近法を含む画像や、部屋全体の画像は適用対象にしない。表面部分として確認できない画像も、参照カードとして保存する。

物体ごとに使用できる部品を検証する。対応する部品には、本体、机の天板、ベッドのマットレス、棚の背、椅子の座面、植木鉢、スマホ画面がある。物体と無関係な部品指定、重複した同面・同用途・同バリエーションの指定、壊れた画像ハッシュは拒否する。

## 解析JSONの受け渡し

起動画面から「画像から資料を作る」を開き、元画像と解析JSONを選択する。現在はCodex/ChatGPTで画像を解析し、構造化した結果を取り込む方式。アプリから有料APIへ送信しない。

`/analysis-contract` で解析担当へ渡す指示とJSON Schemaを取得できる。外側の形式は次の通り。`observation` の中身は表示されるSchemaに従う。

```json
{
  "contract": "manga-blendy.observation",
  "schema_version": 1,
  "source_sha256": "元ファイルのSHA256を小文字の64桁16進数で指定",
  "observation": {}
}
```

画像座標はEXIF補正後の画像を基準に0〜1で指定する。各物体に `management_role` と、必要時に `detail_patches` を追加する。古い解析JSONの省略項目には既定値を使う。

詳細画像指定の一例：

```json
{
  "bbox_xywh": [0.20, 0.65, 0.05, 0.04],
  "description": "カーペットの毛並みだけが見える部分",
  "role": "material",
  "visible_surface": "top",
  "surface_only_verified": true,
  "mapping": {
    "target_part": "body",
    "face": "top",
    "usage": "bump",
    "rotation_degrees": 0,
    "repeat_uv": [4, 4],
    "bump_distance_m": 0.001
  }
}
```

この例の座標は説明用の仮値。`surface_only_verified` は、画像の内容を実際に確認してから設定する。確認できない場合はfalse、`mapping` はnullにする。貼付に適した表面を画像から必ず自動発見できる保証はない。

面は物体のローカル座標で、前=-Y、後=+Y、上=+Z、左=-X、右=+X。部品の面に合わせ、90度単位の向きと繰り返しを保存する。

## 互換性・検証・残る範囲

- 新しいSceneRevisionは版2。版1の保存済み資料も読み込める。既存の原稿・教室実験・採用済み資料を上書きしない。
- 固定家具の分類・小物の重要度は、結果確認画面から新しい改訂として訂正できる。
- 対応表と詳細画像は採用・ZIP書出し・再取込でも維持する。レンダリングへ使う画像は `.blend` に保存し、配布先の絶対パスに依存させない。
- 本番のAPIキー接続は無効化した。APIキーが環境にあっても自動切替しない。ChatGPTログイン試験は変更していない。
- テスト用の合成画像・一室で、分類、予算、重要物保護、旧版読込、元画像ハッシュ、画像の面への適用、色とバンプ、移動後の追従、再読込、ZIPの往復を確認した。
- 新しい部屋では実画像による形状・外観・管理予算の評価が必要。建物・家具の完全再現を保証する万能モデラーではなく、標準テンプレートで足りない形状は実画像に合わせた調整が必要。
- 3つの主役モードと本番1コマ用の外部連動は `背景エンジン連動仕様.md` の追加要件のまま。今回の改修をその実装完了と扱わない。
